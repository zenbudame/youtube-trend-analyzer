# YouTube Trend Analyzer — 条件一致件数・言語・形式別一覧対応版

人気動画・キーワード分析・ゲーム比較・狙い目ランキング・長期トレンド・CSV出力を維持したStreamlitアプリです。

## 今回の変更

- 「表示したい件数」は、取得候補数ではなく**条件に一致する動画の件数**です。
- 各ページで言語・形式・チャンネル規模・最低再生数・登録者比を確認し、不足していれば次のページを検索します。
- 指定件数に達したらその件数だけ表示します。最終ページに余分な一致動画があっても超過しません。重複動画も数えません。
- 検索結果終了・探索上限・APIエラーで不足した場合は、取得済み動画と停止理由を表示します。必ず指定件数を確保できる保証はありません。
- 言語選択を追加しました。日本語・英語・韓国語・中国語など15言語と「すべて」に対応します。
- 個別動画をShorts候補・長尺の別タブに表示し、形式別CSVと全件CSVを保存できます。長さ不明の動画は「形式不明」に分けます。
- 既存の登録者数プリセット/任意範囲、チャンネル総再生数・動画本数、登録者比、小規模チャンネルの条件も利用できます。

## 使い方

1. 左側で動画の言語、登録者数、動画の形式などの条件を設定します。
2. キーワード分析で検索語と期間、「表示したい件数」（例：30件）を指定します。
3. 「分析する」を押します。条件一致が30件になるまで追加検索します。
4. 一致件数・確認した候補数・探索ページ数・停止理由を確認します。
5. Shorts候補/長尺のタブを切り替えて動画を確認します。

「すべて」の形式を選ぶと、指定件数は形式の合計です。各形式で30件ずつ欲しい場合は、形式を指定して各30件の検索を実行してください。ゲーム比較は1タイトルあたり、長期分析は1区間あたりの一致件数を指定します。

条件変更後は実行ボタンを押してください。変更前の結果は非表示にし、再実行を案内します。表示のランキング順だけの変更とCSV保存では再検索しません。ランキングは取得済みの一致動画内での順位です。

## 探索上限

初期値は1回の分析につき20ページ、1ページは最大50候補です。1〜100ページに変更できます。ゲーム比較と長期分析では全対象でこの上限を共有し、各対象を1ページずつ交互に探します。全対象数より上限が小さい場合、未検索の対象は0ページと表示します。

APIでは登録者数の範囲を直接指定できないため、候補取得後に確認し、不足分を追加検索する方式です。検索対象全体を網羅するものではありません。厳しい条件では多くの候補を調べるためAPI利用枠を消費します。足りない場合は条件を緩めるか上限を増やして再実行してください。候補を探す順番も再生数・関連性・新しい順から選べます。

人気動画はAPIの人気一覧をページ送りします。その一覧が尽きた場合、指定件数に達する前でも終了します。

## 言語の判定

検索時に `relevanceLanguage` を指定し、取得後に音声の登録言語 `defaultAudioLanguage` を優先して確認します。音声言語がなければタイトル・説明の登録言語 `defaultLanguage` を使用します。音声や字幕を解析する機能ではありません。

- 初期設定では選択した登録言語と一致する動画だけを含めます。
- 「言語が未登録の動画も含める」をオンにすると、未登録も含めます。別言語と判定できる動画は除外します。
- 英語のen-US/en-GBなどは同じ基本言語として扱います。中国語の簡体字と繁体字は区別します。
- 一覧・CSVに言語コードと判定元を表示します。
- `relevanceLanguage` だけでは言語を厳密に制限できないため、取得後の登録言語確認も行います。人気動画APIではこの検索パラメーターがないため取得後の確認のみです。

## Shortsと長尺の分類

Shorts候補は0秒超〜180秒、長尺は180秒超です。長さ不明・0秒は形式不明です。公開データの長さを使った分類であり、YouTube上のShortsを厳密に判定するものではありません。3分以下の横長の通常動画もShorts候補に含まれます。

Shorts候補の検索ではAPIの `videoDuration=short`（4分未満）を使って候補を減らし、その後180秒以下に絞ります。APIの `long` は20分超のため、長尺検索には使わず、3〜20分の動画も対象にします。

## 登録者数と欠損値

`channels.list(part=statistics)` の `subscriberCount`、`hiddenSubscriberCount`、`viewCount`、`videoCount` を使用します。

- 非公開は「非公開」、応答にチャンネル/登録者数がない場合は「取得不可」と表示し、数値は欠損のまま保持します。0人に置き換えません。
- 登録者数0人は公開された0として扱いますが、登録者比は算出しません。
- 登録者比＝動画の現在の累計再生数÷チャンネルの現在の登録者数。非公開・取得不可・0人の比率は空欄（表では欠損表示）です。無限大や0倍にしません。
- 非公開等は、登録者数条件なしなら含める/常に除外/非公開等のみを選べます。登録者数・登録者比の数値条件がある場合、不明な値は条件を満たしません。
- 総再生数・動画本数も取得できなければ欠損とし、それらの数値条件から除外します。
- APIの登録者数は丸められた値です。境界付近の判定・登録者比は概算です。動画本数は公開動画本数です。

## API呼び出しの節約

同じ分析の各ページ・各ゲーム・各期間で動画IDとチャンネルIDを重複除去し、詳細とチャンネル統計を50件ずつ一括取得します。一度調べたチャンネルは同じ分析中には取り直しません。

API応答は15分間キャッシュします。再実行時も同じリクエストは再利用します。日時条件は15分単位にそろえているため、対象期間の開始には最大15分のずれがあります。APIキーごとにキャッシュを区別します。候補探索のページ数にはキャッシュから読み出したページも含まれるため、実際のネットワーク呼び出し回数と異なる場合があります。

## 無料Web公開・既存アプリの更新

1. ZIPを解凍し、`app.py`、`analyzer.py`、`matching.py`、`requirements.txt`、README等をGitHubリポジトリのルートに配置します。**analyzer.pyとmatching.pyも必須です。** ZIPそのものをアップロードしないでください。
2. 既存アプリは同じリポジトリのファイルを更新します。エントリポイントは引き続き `app.py` です。
3. 新規の場合はStreamlit Community CloudでGitHubを接続して「Create app」、対象リポジトリと `app.py` を指定します。
4. Pythonは3.11以降を使用してください。依存関係はrequirements.txtからインストールされます。
5. Community CloudのSecretsに次を設定します（既存設定があればそのまま使用）。

```toml
YOUTUBE_API_KEY = "取得したAPIキー"
```

キーをGitHubやソースコードへ書かないでください。保存済みキーはサーバーで読み、画面入力欄には埋め込みません。Secrets/環境変数にキーがない場合だけ手動入力欄を表示します。

Community Cloudの無料ホスティングとYouTube APIの利用枠の範囲で運用する構成です。公開アプリの訪問者も保存済みキーのクォータを消費します。常時稼働や無制限利用は保証されません。Google Cloud側でYouTube Data API v3を有効にし、API制限を設定してください。

## ローカル起動

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
```

macOS/Linuxでは `.venv/bin/python` を使用してください。キーは起動後に入力するか、環境変数 `YOUTUBE_API_KEY`、または `.streamlit/secrets.toml` で設定できます。

## 指標と既存機能の注意点

- 動画トレンドスコア：再生速度45%、高評価率25%、コメント率15%、登録者比15%の順位百分率を加重合計。
- ゲーム比較：中央値再生速度55%、サンプル内チャンネル数25%、中央値高評価率20%。
- 狙い目：中央値再生速度40%、登録者比25%、エンゲージメント15%、サンプル内競合の少なさ20%。
- 比率不明は比率の加点を0にするだけで、表示する比率は欠損のままです。条件一致0件のゲームは表に残し、スコア/順位の対象外にします。
- スコアは条件を満たしたサンプル内の相対評価で、YouTube公式指標ではありません。競合数や総再生数を市場全体の値として解釈しないでください。
- 長期分析は元版と同じく30日区間で最大24区間を検索します。期間表示を実際の日付範囲にしました。投稿区間別の「現在の累計再生数」であり、その月に発生した再生数ではありません。チャンネル規模も現在の値です。
- 地域コードJPは日本で視聴可能な動画の条件で、日本語や日本人の投稿だけに限定しません。
- Shorts候補は長さ180秒以下での推定で、縦横比等による厳密な判定ではありません。
- 動画CSVは既存の英語列名を維持し、`channel_total_views`、`channel_video_count`、`subscriber_status` を追加しています。
